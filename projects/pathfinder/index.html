Regulatory Pathfinder

I helped bring AI into a conventional regulatory assurance workspace. Controls, plans and reviews stayed in place. The design work was how people could generate, inspect and accept help without losing the evidence or the decision.

The work was already a register

People were already moving through controls, tests, evidence and incidents. The hard part was not adding another screen. It was helping inside a record that was already dense, without hiding what still had to be judged.

Shaping the experience

These are directions in the working prototype, not dated releases. The move is from a register you scan, to status you can compare, to assistance that stays on the record.

1. Scan the register

Identity, description and definition status in one table.

2. See what needs action

Columns can be reduced so design and operating status stay readable.

3. Assist in place

AI opens on the same record, with the original value still visible.

Help, without leaving the task

A separate chat would have asked people to abandon the control they were judging. I placed assistance on the record itself: suggest an attribute, draft a plan, then leave the result open for review. A suggestion is not a decision.

Suggestions beside the value

When the model disagrees with the source file, the original stays primary. The recommendation and its reason sit next to it. Keep and accept are the only ways the value changes.

Draft from the plan

Pathfinder Agent is an action on the test plan, not another window to go and find. People can ask it to draft, or keep writing. Nothing is saved until they choose to save.

A plan you can still edit

The draft comes back as the plan: method, checks, and the context it used. It stays editable. Generation does not mark the test as approved.

Then read the result

A run can offer a conclusion. The review screen keeps that next to the procedure, the evidence in scope, and whether anyone has reviewed it. The result can still be edited.

From the control to a plan

The useful shift was not a faster blank page. It was starting the plan from the control already on screen, then leaving the checks, the context and the save action in the same document.

Make the output reviewable

A generated conclusion, a reviewed finding and an approved decision are different states. The screen shows the procedure, what was tested, and an edit action, so the output can be checked before anyone treats it as final.

Keep the sources attached

An assisted conclusion is only useful if the sources are still there. Evidence stays inside the same result: the file, what kind of source it is, and whether a step used it.

A recommendation still needs a person

Incident triage can recommend a next step and show the reasoning. Confirm, override and export stay with the practitioner. Where further assessment is outside the current prototype, the screen says so.

What the reviews kept forcing

These are constraints from design reviews with product and engineering, not quoted user research. They changed where AI was allowed to act.

Do not overwrite the source

If the file says Manual and the model suggests something else, the cell cannot update itself. The suggestion has to sit beside the original until someone keeps or accepts it.

Say when the prototype stops

Triage can recommend a next step. Where further assessment is outside the current prototype, the interface says that, and confirm or override stays with the person.

What the design makes possible

Help on the record

Attribute suggestions and plan drafting start from the control already open, not from a blank assistant.

Output you can refuse

Original values, editable plans and review states stay distinct from anything the model proposed.

The same pattern, again

Controls, plans and incidents share the idea that a recommendation waits for a person. No measured rollout is claimed.

Intelligence works best when it fits the workflow

PwC AI Centre of Excellence

Adding an AI capability was only part of the work. The harder question was how it fitted the controls, plans and reviews people were already in.

A new assistant can easily become another place to go. I spent more time on where it appears, what it is allowed to change, and how someone inspects the result before they continue.

The same constraint showed up in attributes, test plans and incidents: a recommendation has to stay visible as a recommendation. Consistency across those moments mattered more than polishing any one screen.

The direction I trust is not a regulatory workflow that feels automated. It is assistance that is useful, understandable, and still accountable to the person reviewing it.
